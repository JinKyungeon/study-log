## 개념 요약
- [[조건문]] — 조건이 `True`일 때만 들여 쓴 코드를 실행. `:`와 들여쓰기가 핵심
- [[조건문]] `else` — 조건이 `False`일 때 할 일. 조건 없이 `else:`만, `if`와 같은 줄 맞춤, 둘 중 **하나만** 실행
- [[조건문]] `elif` — 세 갈래 이상. 위에서부터 검사해 **처음 `True` 하나만** 실행 → 큰 기준부터 위에
- [[반복문]] `for` — `range`가 꺼내는 숫자 개수만큼 들여 쓴 블록을 반복. `range(시작, 끝)`에서 끝은 **미포함**
- [[반복문]] `while` — 조건이 `True`인 동안 반복. 횟수를 모를 때. 블록 안에 조건을 언젠가 `False`로 만드는 줄이 꼭 있어야 함

## 오늘 배운 것 / 헷갈린 것
### 1일차 (2026-10-11) — [[조건문]] `if`
#### 개념
- 지금까진 `True`/`False`를 **보여주기만** 했다면, `if`는 그 결과로 **할 일을 정함**
- 문법: 조건 끝에 `:`, 속한 줄은 **들여쓰기**(표준 스페이스 4칸)
- 들여 쓴 줄 = `if`에 속함 (조건 `True`일 때만) / 안 들여 쓴 줄 = 항상 실행

| 문제 | 내 답 | 결과 | 확인하려는 개념 |
|---|---|---|---|
| 타이핑: 재고 0이면 `품절`, 항상 `확인 끝` | `if` 줄까지 들여 씀 → `IndentationError` → 에러 읽고 수정 | ⚠️→✅ | 들여쓰기는 "위의 `if`에 속한다"는 표시 |
| 타이핑: `stock = 5`이면? | `확인 끝`만 | ✅ | 조건 `False`면 건너뜀 |
| 1. `score = 55`, 두 줄 다 들여 씀 | `채점 완료`만 | ✅ | `False`면 블록 전체 건너뜀 |
| 2. `print("축하합니다")`만 밖으로 | `축하합니다` / `채점 완료` | ✅ | **들여쓰기 한 칸이 의미를 바꿈** |
| 3. 주문 금액 50000원 이상 `무료 배송`, 항상 `주문 접수` | 로직 정답, 안내문 `"주문 금액:"` 공백 누락 → 힌트 후 수정 | ⚠️→✅ | `input` + `if` 종합 |

- `IndentationError: unexpected indent` = 예상 못 한 들여쓰기. `if` 줄 위에는 속할 `if`가 없으니 맨 앞에 써야 함
- 들여쓰기 2칸도 동작하지만 표준은 4칸, 한 블록 안에서는 칸 수를 통일 (섞이면 `IndentationError`)
- 예측 답에 `채점완료`(띄어쓰기 빠짐) → 내용은 정답, 형식은 계속 체크

### 2일차 (2026-10-13) — [[조건문]] `else`
#### 개념
- `if`만 있으면 `False`일 때 **할 일이 없음** → `else`가 그 빈자리를 채움 ("아니면 이걸 해")
- `else` 뒤에는 조건을 안 씀, `:`는 붙음, `if`와 **같은 줄 맞춤**, 아래 할 일만 4칸 들여쓰기
- `if` 블록과 `else` 블록 중 **정확히 하나만** 실행
- `else` 블록이 끝난 뒤 들여쓰기 없는 줄은 항상 실행

#### 문제 의도
| 문제 | 내 답 | 결과 | 확인하려는 개념 |
|---|---|---|---|
| 복습 1. `temp = 15`, `> 20`이면 두 줄, 밖에 `끝` | `끝` | ✅ | 들여 쓴 줄은 한 묶음으로 건너뜀, 밖의 줄은 항상 실행 |
| 복습 2. 나이 입력 → 19세 이상 `성인입니다` | `print("나이:",age)` 추가, `>= 20`, `성인입니다.`, 2칸 → 힌트 후 모두 수정 | ⚠️→✅ | `input` 안내문은 이미 화면에 찍힘 / 조건은 **본문**에서 / 출력 형식 |
| 타이핑: 60점 이상 `합격`, 아니면 `불합격` | 구조 정답, 안내문 `"정수: "` 오타, `>=60` → 수정 | ⚠️→✅ | `else` 모양 (`:`, 줄 맞춤) |
| 1. `money = 3000`, `>= 3500` 버스/걸어간다, 밖에 `출발` | `걸어간다`만 → 힌트 후 `출발` 추가 | ⚠️→✅ | `else` 뒤 들여쓰기 없는 줄도 **끝까지** 확인 |
| 2. 온도 30도 이상 `에어컨 켜기`, 아니면 `창문 열기` | 한 번에 정답 | ✅ | `if`/`else` 혼자 짜기, 경계값(30) 확인 |
| 3. 주문 금액 50000원 이상 배송비 0, 아니면 3000 → `결제 금액 48000원` | 출력 정답 (`print`를 양쪽에 각각 씀) | ✅ | `else` + 계산 + `str()` 종합 |
| 3 다듬기 (2026-10-16). `if`/`else`에서는 `payment_amount`만 정하고 `print`는 밖에 한 번 | `order_amount + 3000 = payment_amount` → `SyntaxError` → 힌트 후 방향 바꿔 해결 | ⚠️→✅ | 블록 안에서는 값만 정하고 공통 줄은 밖으로 / `=`는 오른쪽을 왼쪽 이름에 저장 |

- `Tab` 한 번 = 편집기 설정에 따라 칸 수가 다름. 내 편집기는 2칸이었음 → 4칸으로 맞추기
- 연산자 양옆은 한 칸 띄우기: `>= 60`
- 변수 이름은 소문자 + `_`: `Order_Amount` → `order_amount`
- `#` 주석을 스스로 사용함
- 문제 3 다듬기 완료 (2026-10-16): `SyntaxError: cannot assign to expression` = `=` 왼쪽에는 이름만, 계산식은 오른쪽

### 3일차 (2026-10-19) — 복습 + [[조건문]] `elif`
#### 개념
- `elif` = else + if = "아니면, 혹시 이건가?" → 조건 있음, 끝에 `:`, `if`와 같은 줄 맞춤, 여러 개 가능
- 위에서부터 검사하다 **처음으로 `True`인 것 하나만** 실행, 나머지는 검사도 안 함
- 그래서 `elif dust >= 31`에 "81 미만"을 따로 안 써도 됨 (여기까지 왔다 = 위 조건이 `False`)
- `>=`로 단계를 나눌 땐 **큰 기준부터 위에**
- 이상·이하 → `=` 붙음(포함), 초과·미만 → `=` 없음

#### 문제 의도
| 문제 | 내 답 | 결과 | 확인하려는 개념 |
|---|---|---|---|
| 복습 1. `temperature = 28`, `>= 30`이면 에어컨/아니면 창문, 밖에 `공부 시작` | `창문을 연다` / `공부 시작` | ✅ | 블록 밖의 줄까지 **끝까지** 읽기 (10/13 `출발` 누락 재도전) |
| 복습 2. 학생 수 입력 → 20명 이상 큰 강의실, 아니면 작은 강의실 (`room`에 값만, `print`는 밖에 한 번) | 처음엔 양쪽 블록에 `print`, 안내문 `"학생 수:"` 공백 누락 → 힌트 후 `room = "큰 강의실"`로 해결 | ⚠️→✅ | 블록 안에서는 값만 정하기 / `=` 방향 (10/16 재도전) / 안내문 공백 |
| 타이핑: 미세먼지 농도 입력 → 81 이상 나쁨, 31 이상 보통, 그 외 좋음 | 구조 정답, `grade ='' "보통"` 오타 → 힌트 후 수정. 100·50·20으로 세 갈래 확인 | ⚠️→✅ | `elif` 모양 / 갈래마다 입력값을 골라 테스트 |
| 1. 경계값 예측 81·80·31·30 | 나쁨·보통·보통·좋음 | ✅ | `>=`는 경계 숫자 포함 |
| 2. 순서 함정: `score = 95`, `>= 60`이 맨 위 | `학접: C` (내용 정답, `학점` 오타) | ✅ | **처음 `True` 하나만** → 조건 순서가 결과를 바꿈 |
| 3. 점수 → A/B/C/F (`elif` 2개) | 한 번에 정답, 95·85·75·50 모두 확인 | ✅ | `elif` 여러 개 + 큰 기준부터 / 블록 안에서 값만 |

- `str(room)` — `room`은 이미 글자(`str`)라서 `str()` 필요 없음. `str()`은 숫자 → 글자일 때
- `'' "보통"` — 붙어 있는 문자열은 하나로 이어 붙음, `''`은 빈 문자열 → 에러 없이 `보통`. **에러 안 나는 오타**라 코드도 훑어보기
- 주석 실무 스타일: 코드 **위에**, `# ` 한 칸, "무엇"보다 **"왜"** (예: `# 큰 기준부터 검사해야 함`), 범위는 `80 이상 90 미만`처럼 정확히
- 앞으로 문제마다 **추천 영어 변수 이름**을 같이 받기로 함. 단어 연결은 `_` (snake_case): `student_count`

### 4일차 (2026-10-20) — 복습 + [[반복문]] `for`
#### 개념
- 같은 일을 여러 번 → `for i in range(5):` + 들여 쓴 블록
- `i` = 지금 꺼낸 숫자를 담는 **변수**, 반복할 때마다 값이 바뀜
- `range(5)` → `0, 1, 2, 3, 4` (**0부터**, 5개) / `range(1, 6)` → `1 ~ 5`
- **끝은 "멈춤 표시"라 미포함** → 개수 = 끝 − 시작. 이어 붙여도(`range(0, 5)`, `range(5, 10)`) 겹치거나 빠지는 숫자 없음
- `if`와 똑같이 블록 안 vs 밖: `if` 블록은 0번 또는 1번, `for` 블록은 `range` 개수만큼
- **누적 패턴**: 반복 **전** `total_score = 0`, 반복 **안** `total_score = total_score + score`, 출력은 반복 **후**

#### 문제 의도
| 문제 | 내 답 | 결과 | 확인하려는 개념 |
|---|---|---|---|
| 복습 1. `stock = 0`, `if >= 10` / `elif >= 1`, `else` 없음, 밖에 `확인 완료` | `확인완료` → 힌트 후 `확인 완료` | ⚠️→✅ | `else`가 없으면 다 `False`일 때 **아무 블록도 실행 안 됨** (`else`는 자동으로 안 생김) |
| 복습 2. 구매 금액 → 100000 이상 10000원, 50000 이상 3000원, 그 외 0원 할인 | 구조 한 번에 정답, 안내문 `"구매 금액:"` 공백 누락 → 힌트 후 수정 | ⚠️→✅ | `elif` 순서 / 블록 안에서 값만 / `str()+"원"` / `int(input())` 종합 |
| 타이핑: `range(1, 4)`로 `번째 반복`, 밖에 `반복 끝` | 실행 정상. 처음 "반복 끝 3번"이라 함 → 힌트 후 "번째 반복 3번, 반복 끝은 밖이라 1번" | ⚠️→✅ | 블록 안 = 반복, 밖 = 1번 |
| 1. `range(3)`, `print("줄", i)`, 밖에 `끝` 예측 | `0줄 1줄 2줄` → 힌트 후 `줄 0 / 줄 1 / 줄 2 / 끝` | ⚠️→✅ | `range(3)`은 0부터 / `print`는 괄호 안 **순서대로** |
| 2. `range(2, 5)`, `print(i * 10)` 예측 | `20 30 40` | ✅ | 끝(5) 미포함 / `i`를 계산에 쓰기 |
| 3. 구구단 (`number` 입력, 1~9) | `range(1, 10)` 정답. 처음엔 결과만 출력 → 수식 추가, `X` → 힌트 후 `x`, `str()` 빼고 쉼표로 | ⚠️→✅ | 끝 미포함 직접 적용 / 변하는 값(`i`) vs 고정 값(`number`) / 쉼표면 `str()` 불필요 |
| 4. 학생 3명 점수 → A/B/C, 마지막에 총점 (`input` 한 번만) | 등급 부분 한 번에 정답 (`input(str(i)+"번 학생 점수: ")` 스스로). 총점 `score(i)` → 힌트 후 누적 패턴으로 해결 | ⚠️→✅ | `input` 안내문은 하나의 글자로 / `for` 안 `if` (8칸) / 덮어쓰기 vs **누적** |

- `range`의 끝이 왜 안 들어가는지 **스스로 질문** → 개수 = 끝 − 시작, 자 눈금 비유
- `input()`은 `print`처럼 쉼표로 조각을 못 받음 → `str(i)+"번 학생 점수: "`처럼 `+`로 하나의 글자를 만들어 넣기
- `score(i)` — 변수 뒤 괄호는 함수 호출 모양 → `TypeError: 'int' object is not callable`. 지난 점수는 덮어써져서 남아 있지 않음 → 따로 쌓을 변수 필요
- 쉼표 앞 공백 `"=" ,` — 동작은 같지만 `"=",`처럼 붙여 쓰는 게 보기 좋음
- 빈 줄로 단계(입력 → 판단 → 출력 → 누적)를 나눠 읽기 좋게 씀

### 5일차 (2026-10-26) — 복습 + [[반복문]] `while`
#### 개념
- `for` = "**몇 번**?" (횟수를 앎) / `while` = "**언제까지**?" (조건만 앎)
- `while 조건:` — `if`와 모양은 같지만 블록 실행 후 **다시 조건으로 돌아가** 검사, `False`면 탈출
- 블록 안에 조건을 바꾸는 줄(`count = count + 1`, 다시 `input`)이 없으면 **무한 반복** → 코랩 ■ 정지 버튼
- 0부터 1씩 더하면 **마지막 값 = 반복 횟수** (`range(5)`가 5개인 것과 같은 원리)
- 줄마다 "**몇 번** 실행돼야 하지?" → 반복 전 1번 / 블록 안 매번 / 반복 후 1번 → 위치가 정해짐

#### 문제 의도
| 문제 | 내 답 | 결과 | 확인하려는 개념 |
|---|---|---|---|
| 복습 1. `range(1, 5)`, `print(i * 2)`, 밖에 `끝` 예측 | `2 4 6 8 끝`, "끝은 바깥" | ✅ | 끝 미포함 / 블록 안·밖 |
| 복습 2. 3일 매출 입력 → `총 매출 40000원` | 구조 한 번에 정답 (`total_sales = 0` 위치 스스로). `daily_salse`/`daily_sales` 오타로 `3원` → 질문 후 스스로 발견 | ⚠️→✅ | 누적 패턴 재도전 / 이름은 글자 그대로 비교 |
| 타이핑: `water < 5`, 물 한 컵 마심 예측 | 마지막 `water` 5 정답, 출력 횟수 4번 → 표 힌트 후 5번 | ⚠️→✅ | 0부터 시작 → 횟수 세기 |
| 1. `money = 10000`, 3000씩 빼기 예측 | 3번, `7000 4000 1000`, 마지막 1000 | ✅ | 빼기 **후** 출력 / 조건 `False`면 탈출 |
| 2. 비밀번호 `1234` 맞을 때까지 입력 | 첫 입력을 `while` 전에 준비 스스로. 블록 안 `password != int(input(...))` → 무한 반복 → 질문 후 `=`로 해결 | ⚠️→✅ | `while` 전 변수 준비 / `=`(담기) vs `!=`(비교) |
| 2 다듬기. `int()` 빼고 글자로, 불필요한 줄·괄호·`str()` 지우기 | 3개 중 1개만 지움 → 표로 체크 후 모두 정리. 보너스 `correct_password` 변수로 완성 | ⚠️→✅ | `input()`은 이미 `str` / 바뀔 수 있는 값은 이름 붙여 한 곳에 |

- 코랩은 이전에 실행한 변수를 **기억** → 오타가 있어도 `NameError` 대신 옛값(유령 변수)으로 엉뚱한 결과. 이상하면 **런타임 → 세션 다시 시작**
- 비밀번호는 계산할 숫자가 아니라 글자 → `int()`면 `abcd` 입력 시 에러, `"1234"`와 글자끼리 비교
- `"correct_password"`(글자 그대로) vs `correct_password`(그릇 안의 값)
- 매출 문제 최종 코드는 `salse`로 통일 → 동작은 하지만 영어 철자는 `sales`
- 혼자 해내고 싶다고 함 → 정답 대신 질문으로 스스로 찾기
