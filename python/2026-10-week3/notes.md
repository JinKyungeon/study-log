## 오늘 배운 것 / 헷갈린 것
### 1일차 (2026-10-11) — [[조건문]] `if`
#### 개념
- 지금까진 `True`/`False`를 **보여주기만** 했다면, `if`는 그 결과로 **할 일을 정함**
- 문법: 조건 끝에 `:`, 속한 줄은 **들여쓰기**(표준 스페이스 4칸)
- 들여 쓴 줄 = `if`에 속함 (조건 `True`일 때만) / 안 들여 쓴 줄 = 항상 실행

| 문제 | 내 답 | 결과 | 확인하려는 개념 |
|---|---|---|---|
| 타이핑: 재고 0이면 `품절`, 항상 `확인 끝` | `if` 줄까지 들여 씀 → `IndentationError` → 에러 읽고 수정 | ⚠️→✅ | 들여쓰기는 "위의 `if`에 속한다"는 표시 |
| 타이핑: `stock = 5`이면? | `확인 끝`만 | ✅ | 조건 `False`면 건너뜀 |
| 1. `score = 55`, 두 줄 다 들여 씀 | `채점 완료`만 | ✅ | `False`면 블록 전체 건너뜀 |
| 2. `print("축하합니다")`만 밖으로 | `축하합니다` / `채점 완료` | ✅ | **들여쓰기 한 칸이 의미를 바꿈** |
| 3. 주문 금액 50000원 이상 `무료 배송`, 항상 `주문 접수` | 로직 정답, 안내문 `"주문 금액:"` 공백 누락 → 힌트 후 수정 | ⚠️→✅ | `input` + `if` 종합 |

- `IndentationError: unexpected indent` = 예상 못 한 들여쓰기. `if` 줄 위에는 속할 `if`가 없으니 맨 앞에 써야 함
- 들여쓰기 2칸도 동작하지만 표준은 4칸, 한 블록 안에서는 칸 수를 통일 (섞이면 `IndentationError`)
- 예측 답에 `채점완료`(띄어쓰기 빠짐) → 내용은 정답, 형식은 계속 체크

### 2일차 (2026-10-13) — [[조건문]] `else`
#### 개념
- `if`만 있으면 `False`일 때 **할 일이 없음** → `else`가 그 빈자리를 채움 ("아니면 이걸 해")
- `else` 뒤에는 조건을 안 씀, `:`는 붙음, `if`와 **같은 줄 맞춤**, 아래 할 일만 4칸 들여쓰기
- `if` 블록과 `else` 블록 중 **정확히 하나만** 실행
- `else` 블록이 끝난 뒤 들여쓰기 없는 줄은 항상 실행

#### 문제 의도
| 문제 | 내 답 | 결과 | 확인하려는 개념 |
|---|---|---|---|
| 복습 1. `temp = 15`, `> 20`이면 두 줄, 밖에 `끝` | `끝` | ✅ | 들여 쓴 줄은 한 묶음으로 건너뜀, 밖의 줄은 항상 실행 |
| 복습 2. 나이 입력 → 19세 이상 `성인입니다` | `print("나이:",age)` 추가, `>= 20`, `성인입니다.`, 2칸 → 힌트 후 모두 수정 | ⚠️→✅ | `input` 안내문은 이미 화면에 찍힘 / 조건은 **본문**에서 / 출력 형식 |
| 타이핑: 60점 이상 `합격`, 아니면 `불합격` | 구조 정답, 안내문 `"정수: "` 오타, `>=60` → 수정 | ⚠️→✅ | `else` 모양 (`:`, 줄 맞춤) |
| 1. `money = 3000`, `>= 3500` 버스/걸어간다, 밖에 `출발` | `걸어간다`만 → 힌트 후 `출발` 추가 | ⚠️→✅ | `else` 뒤 들여쓰기 없는 줄도 **끝까지** 확인 |
| 2. 온도 30도 이상 `에어컨 켜기`, 아니면 `창문 열기` | 한 번에 정답 | ✅ | `if`/`else` 혼자 짜기, 경계값(30) 확인 |
| 3. 주문 금액 50000원 이상 배송비 0, 아니면 3000 → `결제 금액 48000원` | 출력 정답 (`print`를 양쪽에 각각 씀) | ✅ | `else` + 계산 + `str()` 종합 |
| 3 다듬기 (2026-10-16). `if`/`else`에서는 `payment_amount`만 정하고 `print`는 밖에 한 번 | `order_amount + 3000 = payment_amount` → `SyntaxError` → 힌트 후 방향 바꿔 해결 | ⚠️→✅ | 블록 안에서는 값만 정하고 공통 줄은 밖으로 / `=`는 오른쪽을 왼쪽 이름에 저장 |

- `Tab` 한 번 = 편집기 설정에 따라 칸 수가 다름. 내 편집기는 2칸이었음 → 4칸으로 맞추기
- 연산자 양옆은 한 칸 띄우기: `>= 60`
- 변수 이름은 소문자 + `_`: `Order_Amount` → `order_amount`
- `#` 주석을 스스로 사용함
- 문제 3 다듬기 완료 (2026-10-16): `SyntaxError: cannot assign to expression` = `=` 왼쪽에는 이름만, 계산식은 오른쪽

### 3일차 (2026-10-19) — 복습 + [[조건문]] `elif`
#### 개념
- `elif` = else + if = "아니면, 혹시 이건가?" → 조건 있음, 끝에 `:`, `if`와 같은 줄 맞춤, 여러 개 가능
- 위에서부터 검사하다 **처음으로 `True`인 것 하나만** 실행, 나머지는 검사도 안 함
- 그래서 `elif dust >= 31`에 "81 미만"을 따로 안 써도 됨 (여기까지 왔다 = 위 조건이 `False`)
- `>=`로 단계를 나눌 땐 **큰 기준부터 위에**
- 이상·이하 → `=` 붙음(포함), 초과·미만 → `=` 없음

#### 문제 의도
| 문제 | 내 답 | 결과 | 확인하려는 개념 |
|---|---|---|---|
| 복습 1. `temperature = 28`, `>= 30`이면 에어컨/아니면 창문, 밖에 `공부 시작` | `창문을 연다` / `공부 시작` | ✅ | 블록 밖의 줄까지 **끝까지** 읽기 (10/13 `출발` 누락 재도전) |
| 복습 2. 학생 수 입력 → 20명 이상 큰 강의실, 아니면 작은 강의실 (`room`에 값만, `print`는 밖에 한 번) | 처음엔 양쪽 블록에 `print`, 안내문 `"학생 수:"` 공백 누락 → 힌트 후 `room = "큰 강의실"`로 해결 | ⚠️→✅ | 블록 안에서는 값만 정하기 / `=` 방향 (10/16 재도전) / 안내문 공백 |
| 타이핑: 미세먼지 농도 입력 → 81 이상 나쁨, 31 이상 보통, 그 외 좋음 | 구조 정답, `grade ='' "보통"` 오타 → 힌트 후 수정. 100·50·20으로 세 갈래 확인 | ⚠️→✅ | `elif` 모양 / 갈래마다 입력값을 골라 테스트 |
| 1. 경계값 예측 81·80·31·30 | 나쁨·보통·보통·좋음 | ✅ | `>=`는 경계 숫자 포함 |
| 2. 순서 함정: `score = 95`, `>= 60`이 맨 위 | `학접: C` (내용 정답, `학점` 오타) | ✅ | **처음 `True` 하나만** → 조건 순서가 결과를 바꿈 |
| 3. 점수 → A/B/C/F (`elif` 2개) | 한 번에 정답, 95·85·75·50 모두 확인 | ✅ | `elif` 여러 개 + 큰 기준부터 / 블록 안에서 값만 |

- `str(room)` — `room`은 이미 글자(`str`)라서 `str()` 필요 없음. `str()`은 숫자 → 글자일 때
- `'' "보통"` — 붙어 있는 문자열은 하나로 이어 붙음, `''`은 빈 문자열 → 에러 없이 `보통`. **에러 안 나는 오타**라 코드도 훑어보기
- 주석 실무 스타일: 코드 **위에**, `# ` 한 칸, "무엇"보다 **"왜"** (예: `# 큰 기준부터 검사해야 함`), 범위는 `80 이상 90 미만`처럼 정확히
- 앞으로 문제마다 **추천 영어 변수 이름**을 같이 받기로 함. 단어 연결은 `_` (snake_case): `student_count`
