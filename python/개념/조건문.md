# 조건문 (if)

## 한 줄 정의
조건이 **`True`일 때만** 들여 쓴 코드를 실행한다.

## 왜 필요한가
[[불]]로 `True`/`False`를 **보여주기만** 하던 것에서, 그 결과에 따라 **다른 일을 하게** 만든다.
- 미세먼지 80 초과 → "마스크 착용" 안내
- 재고 0 → "품절" 표시
- 주문 금액 50000원 이상 → "무료 배송"

## 기본 모양
```python
dust = 95

if dust > 80:                    # ← 조건 끝에 콜론 :
    print("마스크를 착용하세요")    # ← 들여쓰기(4칸): if에 속함, True일 때만
print("측정 완료")                # ← 들여쓰기 없음: 항상 실행
```
- `dust = 95` → `마스크를 착용하세요` / `측정 완료`
- `dust = 50` → `측정 완료`만

## 문법 규칙
1. 조건 끝에 **콜론 `:`**
2. 속한 줄은 **들여쓰기** (표준 스페이스 4칸, `Tab`)
   - 한 블록 안에서는 칸 수를 똑같이 (섞이면 `IndentationError`)
   - 비유: 보고서의 하위 항목처럼 안으로 들어간 줄은 위의 `if`에 속한다

## 들여쓰기 한 칸이 의미를 바꾼다
```python
score = 55
if score >= 60:
    print("합격")
print("축하합니다")   # if 밖 → 불합격이어도 출력됨!
print("채점 완료")
```

## `else` — 아니면
```python
score = int(input("점수: "))

if score >= 60:
    print("합격")
else:                  # ← 조건 없음, 콜론만. if와 같은 줄 맞춤
    print("불합격")
```
- `else` = "위 조건이 아닌 모든 경우" → 조건을 쓰지 않는다
- `if` 블록과 `else` 블록 중 **정확히 하나만** 실행된다
- `else` 블록 뒤의 들여쓰기 없는 줄은 항상 실행된다
- 경계값 확인: "이상"이면 그 숫자를 직접 넣어 본다 (`>=` vs `>`)

### 블록 안에서는 값만 정하고, 공통 줄은 밖으로
```python
order_amount = int(input("주문 금액: "))

if order_amount >= 50000:
    payment_amount = order_amount
else:
    payment_amount = order_amount + 3000
print("결제 금액", str(payment_amount)+"원")   # 두 경우 공통 → 밖에 한 번만
```

## 자주 하는 실수
- `if` 줄 자체를 들여 씀 → `IndentationError: unexpected indent` (2026-10-11 실수, 에러 읽고 스스로 해결)
- 콜론 `:` 빠뜨림 → `SyntaxError`
- 조건에 `=` 사용 → 비교는 `==` ([[불]])
- `input` 안내문이 이미 화면에 나오는데 같은 내용을 `print`로 또 출력 (2026-10-13)
- 예측할 때 `if`/`else`만 보고 그 아래 들여쓰기 없는 줄을 빠뜨림 (2026-10-13)
- `order_amount + 3000 = payment_amount` → `SyntaxError: cannot assign to expression`. 저장할 이름은 `=` 왼쪽 ([[변수]], 2026-10-16)

## 관련 개념
- [[불]] — `if`는 조건의 `True`/`False`를 보고 실행 여부를 정한다
- [[input]] — 입력값으로 조건을 따질 땐 `int()` 먼저
- 다음: `elif`(여러 조건)
