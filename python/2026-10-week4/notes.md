## 개념 요약
- [[print]] 쉼표 = 공백 **한 칸**, `+` = 붙이기 (숫자는 `str()`로 바꾼 뒤)
- [[반복문]] 누적 — `total = 0`은 반복 **밖 위**, 더하기는 **안**, 결과 출력은 **밖 아래**
- [[반복문]] `while` 조건 = "**계속 반복할** 조건" (목표를 넘을 수 있으면 `!=` 말고 `<`)
- `%` = 나눈 나머지. `day % 2 == 0` → 짝수인가? (처음 등장)

### 1일차 (2026-10-28) — 복습 4문제

| 문제 | 내 답 | 결과 | 확인하려는 개념 |
|---|---|---|---|
| 1. 예측: `range(1, 5)` + `day % 2 == 0`이면 쿠폰 누적, 아니면 꽝 | 표 건너뜀 → `4 일차 꽝`, `쿠폰 수:  2 ` (공백 두 칸) → 질문 후 정답 | ⚠️→✅ | `for`+`if/else` 갈래, 누적, 쉼표 공백 한 칸 |
| 2. 상자 3개 무게 입력 → 10 이상 `무거움`/`가벼움`, 총 무게 `27kg` | 한 번에 정답 (형식까지) | ✅ | `for`+`input`+`if/else`+누적, `>=` 경계값, `str()+"kg"` |
| 3. 계단 50칸까지 입력만큼 오르기, 몇 번 만에 도착 | 한 번에 정답 (실행 결과도 예시와 같음) | ✅ | `while` 조건 `<`, 저장 두 개, `=`로 입력 담기 |
| 4. 예측: `battery` 10에서 15씩, `< 50`인 동안 + `>= 40`이면 충분/부족 | **표를 채워서** 계산 모두 정답, `25부족`·`충전 3번` 공백 누락 → 질문 후 정답, 4번째 검사 `55 < 50` False 정답 | ⚠️→✅ | `while` 조건은 바퀴 **시작할 때만** 검사, 넘는 값(55)도 출력, 경계값 `40 >= 40`, 쉼표 수 = 공백 수 |

- 문제 1 실수: `4 일차 꽝`인데 `쿠폰 수: 2` → **서로 맞지 않음**. 예측이 끝나면 "누적값 = 해당 줄 개수?"로 스스로 확인하기
- 문제 1 실수: 표를 건너뛰었고, 틀린 곳이 바로 4바퀴째였음 → **예측은 표부터**
- 문제 4: 표를 채우니 계산은 한 번에 정답 → 남은 실수는 쉼표 공백뿐. 예측 답을 적은 뒤 **쉼표 수 = 공백 수** 세어 보기
- 문제 3: 3주차 약점(조건 뒤집기·저장 누락·`=`/`!=`)이 하나도 안 나옴

### 문제 의도 — 무슨 개념을 확인하려고 낸 문제인가
| 문제 | 코드 | 확인하려는 개념 |
|---|---|---|
| 1. 쿠폰 예측 | `if day % 2 == 0:` 안에서만 `coupon_count + 1` | 바퀴마다 갈래를 새로 정함 / 누적은 한 블록에서만 늘어남 / 쉼표 = 공백 한 칸 (3주차 마무리 예측 2와 같은 구조) |

| 4. 배터리 예측 | 블록 안에서 `battery + 15` 후 `if` | 조건 검사 시점(바퀴 시작), 목표를 넘은 값도 그 바퀴에선 출력, 표로 바퀴 건너뛰기 방지 |
| 3. 계단 오르기 | `while current_stairs < goal_stairs:` | 목표를 **넘어도** 멈춰야 하므로 `<` (`!=`면 53에서 무한 반복), 누적·횟수 둘 다 저장 (10/26 저금, 10/27 물병 문제의 복습) |

### 2일차 (2026-10-29) — 복습 3문제

| 문제 | 내 답 | 결과 | 확인하려는 개념 |
|---|---|---|---|
| 1. 계단 오르기 안 보고 다시 짜기 | 구조 한 번에 정답, 마지막 줄 `str(climb_count)+"번 만에 도착"` → `3번`(공백 없음) → 질문 후 쉼표로 수정 | ⚠️→✅ | `while` 조건 `<`, 저장 두 개, 위치 3곳 / `,`(자동 공백) vs `+`(직접 공백) |
| 2. 예측: `money` 1000에서 300씩, `while money > 0` + `>= 0`이면 남은 돈/모자람 | **표 4바퀴 모두 정답** (`-200`, `else`까지), 5번째 검사·`총 4 일` 줄은 표에서 빠짐 → 질문 후 정답 | ⚠️→✅ | 조건 검사 시점, 음수·경계값 `>= 0`, 반복 **끝난 뒤** 줄까지 읽기 |
| 3. 3명 나이 입력 → 13세 이상 `입장 가능`/`보호자 필요`, 입장 가능 수 | 결과 한 번에 정답 (형식까지), 추가 조건(비교 결과를 변수에 담기)을 건너뜀 → 질문 후 `is_allowed = age >= 13`, `if is_allowed:` | ⚠️→✅ | `input`+`int()`, `str(i)+"번 …"`, `for`+`if/else`+누적, 🆕 불 변수 `is_` |

- 문제 1: `,`와 `+` 공백 차이 — `+`로 붙이면 공백은 **내가** 따옴표 안에 넣어야 함 (`str(climb_count)+" 번 만에 도착"`도 정답)
- 문제 2: 어제와 달리 표를 채우니 4바퀴째도 정답. 다음부터 표 맨 아래에 **"마지막 검사 → False → 밖으로"** 한 줄 추가
- 문제 3: 쉼표 vs `+`를 예시 보고 스스로 골랐음 (`1번 입장 가능` → `+`). 남은 실수는 문제 **추가 조건** 읽기

### 문제 의도 — 2일차
| 문제 | 코드 | 확인하려는 개념 |
|---|---|---|
| 1. 계단 다시 짜기 | `while current_stairs < goal_stairs:` | 어제 구조가 기억에 남았는지 (조건 `<`, 누적·횟수 저장, 위치 3곳) + 출력 형식 |
| 2. 돈 예측 | `while money > 0:` 안에서 빼고 `if money >= 0:` | 바퀴 시작에만 조건 검사 → `-200`이 돼도 그 바퀴는 출력, 반복이 끝난 뒤 `print`까지 |
| 3. 입장 확인 | `is_allowed = age >= 13` → `if is_allowed:` | 비교 결과(`True`/`False`)도 값이라 변수에 담을 수 있음 (2주차 [[불]] 복습), `if`는 결국 불 값 하나를 봄 |

- 문제 3: 문제 1에서 배운 `is_` 불 변수를 **바로 혼자** 적용, 예전 약점(블록 안에서 값만)도 한 번에
